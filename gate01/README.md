# Gate1 提出物（NEXUS55 / L1 #1 完全な要件定義書からの実装）

社内問い合わせ管理システム「ステータス変更・担当者割り当て機能」（要件定義書 v1.2）の実装です。
Python 3.10+ / Flask / SQLite で作りました。

## 1. 起動手順

```bash
cd gate01
pip install -r requirements.txt
python init_db.py        # DB を作成し、動作確認用データを投入（何度でも作り直せます）
python app.py            # http://127.0.0.1:5000 で起動
```

ログイン機能と一覧画面は「実装済み」という想定のため、今回の範囲外です。ただ、それが無いと権限の出し分けや[一覧に戻る]を確認できないので、**既存機能の代わりとして最小限のスタブ**（ユーザーを選ぶだけのログイン、件名が並ぶだけの一覧）を置いています。仕様にある機能を増やすものではありません。

## 3. 実装できなかった箇所

- **V-03 の五十音順**：users テーブルに読み仮名のカラムが無く、漢字氏名を正しく五十音順に並べられません。仕様外のカラムは追加せず、氏名の文字コード順で並べています。
- **ステータス変更のコメントの保存先**：画面にはコメント欄（200字以内）がありますが、データ定義に保存先のカラムがありません。文字数チェックだけ行い、保存はしていません。
- 仕様外の機能は追加していません。N-01（ロールバック）の確認は、アプリ本体には手を入れず、テストの中で履歴登録の処理だけを失敗する処理に差し替えて行いました。

## 6. 振り返り


6-1. 実装前に判断に迷った箇所はありましたか。あったなら、それは仕様書のどこが不足していたからですか。

あった。「確定度100%」とされていたが、次の箇所は仕様書に書かれていなかった。
- V-03「氏名の五十音順」：users テーブルに読み仮名のカラムが無く、漢字の氏名では五十音順に並べられない（データ定義と表示ルールの不整合）
- コメント欄：画面仕様に「コメント（任意・200字以内）」があるのに、保存先のカラムがデータ定義に無い
- ADMIN が NEW 以外の問い合わせを未割り当てに戻そうとしたときのエラー文言が 2.8 に無い（R-05 違反なので「権限なし」の文言を流用した）
- NEW→IN_PROGRESS で担当者を自動設定したときの履歴：ステータスの履歴だけか、担当者の履歴も残すのかが書かれていない（画面例に2行並んでいたので2件登録にした）
- 複数のエラー条件に同時に当てはまるとき（例：DONE かつ MEMBER）に、どのメッセージを優先するかの順序が無い
- ステータス変更に役割（ADMIN/MEMBER）の制限があるのかどうかが書かれていない（書かれていないので制限なしにした）

6-2. 最初の AI プロンプトを見返して、要件定義書のどの部分を伝え忘れましたか。

配布資料の PDF を AI にそのまま読ませたので、要件定義書の内容で伝え忘れた部分は無い。
ただし、最初のプロンプト自体は「手伝ってほしい」だけで、「書いていないことを足さない」「文言を句読点まで一致させる」「実装できない箇所は README に書く」といった進め方の制約を自分の言葉で指示していなかった。AI が PDF の注意事項から読み取ってくれたので結果的に問題は無かったが、仕様書を渡さない場面では抜けやすい部分だと思う。

6-3. もしこの要件定義書が無く、「問い合わせのステータスを変えられるようにして」とだけ言われていたら、何を確認しに行きましたか。（10 個以上）

**目的・範囲**
1. 何のために変えたいのか（対応漏れを防ぎたい？ 進捗を依頼者に見せたい？）
2. 誰が使うのか（情報システム部だけか、依頼した社員も見るのか）
3. ステータスの種類と、それぞれの意味（「保留」は必要か、「却下」「重複」は要るか）
4. どのステータスからどのステータスへ変えてよいか（完了から戻せるか、未対応からいきなり完了にできるか）

**権限**
5. 誰がステータスを変えられるか（担当者だけか、誰でもか、管理者だけか）
6. 担当者の決め方（自分で取るのか、管理者が割り振るのか、変更は誰ができるか）
7. 退職・異動した人（無効ユーザー）をどう扱うか

**付随処理・記録**
8. 変更の履歴を残すか。残すなら何を（誰が・いつ・何から何へ）
9. 完了日時などの日時を記録するか。再オープンしたらどうするか
10. 変更のときにコメントを残すか。文字数の上限や必須かどうか
11. ステータスが変わったら誰かに通知するか（依頼者へのメールなど）

**画面・メッセージ**
12. どの画面のどこで変更するのか（詳細画面か、一覧から一括でか）
13. 成功・エラーのときに出すメッセージの文言
14. 選べない選択肢は非表示にするか、グレーアウトにするか

**非機能**
15. 2人が同時に同じ問い合わせを変えたときにどうするか
16. 途中で失敗したときにどこまで元に戻すか
17. いつまでに必要か、既存のデータ（今あるステータス）をどう移行するか
