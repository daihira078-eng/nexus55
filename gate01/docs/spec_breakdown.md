# 要件定義書 v1.2 → 実装単位への分解

## A. 状態遷移（2.4）— 配点30
| 変更前 | 許可される変更先 |
|---|---|
| NEW | IN_PROGRESS |
| IN_PROGRESS | PENDING, DONE |
| PENDING | IN_PROGRESS |
| DONE | IN_PROGRESS（再オープン） |

- 実装：`TRANSITIONS` 辞書1か所で定義し、画面（V-01）とサーバー検証の両方がこれを参照する
- 表外の遷移 → 「このステータスへは変更できません。画面を再読み込みしてください。」

## B. 付随処理（2.5）
| 遷移 | 処理 |
|---|---|
| NEW → IN_PROGRESS | assignee_id が NULL なら操作者を設定 |
| * → DONE | closed_at = 現在日時 |
| DONE → IN_PROGRESS | closed_at = NULL |
| 全遷移 | 履歴1件登録 ＋ updated_at 更新 |

## C. 担当者ルール（2.6）— 配点25（B と合わせて）
| No | 実装 | エラー文言 |
|---|---|---|
| R-01 | 指定ユーザーが存在しない / is_active=false なら拒否 | 指定されたユーザーは選択できません。 |
| R-02 | status=DONE なら拒否 | 完了済みの問い合わせは担当者を変更できません。 |
| R-03 | MEMBER は「assignee=NULL を自分に」だけ許可 | この操作を行う権限がありません。 |
| R-04 | ADMIN は任意の有効ユーザーに割り当て可 | — |
| R-05 | NULL に戻すのは ADMIN かつ status=NEW のみ | この操作を行う権限がありません。 |
| R-06 | 担当者変更でも履歴1件登録 | — |

## D. 表示ルール（2.7）— 配点20（E と合わせて）
| No | 実装 |
|---|---|
| V-01 | ラジオは TRANSITIONS[現在] の値のみ |
| V-02 | 変更先0件ならステータス変更セクションごと非表示 |
| V-03 | プルダウン＝有効ユーザーのみ・氏名順。先頭「未割り当て」は ADMIN のみ |
| V-04 | MEMBER かつ担当者設定済み → ボタン非活性＋「担当者の変更は管理者に依頼してください」 |
| V-05 | DONE → 担当者変更ボタン非活性 |
| V-06 | 優先度 HIGH=高(赤) / MIDDLE=中(黒) / LOW=低(灰) |
| V-07 | 履歴0件 →「変更履歴はありません」。新しい順・最大20件 |

## E. メッセージ9種（2.8）＋ N-02
成功（緑）：
1. ステータスを「{表示名}」に変更しました。
2. 担当者を「{氏名}」に変更しました。
3. 担当者を未割り当てに戻しました。

エラー（赤）：
4. このステータスへは変更できません。画面を再読み込みしてください。
5. この操作を行う権限がありません。
6. 完了済みの問い合わせは担当者を変更できません。
7. 指定されたユーザーは選択できません。
8. コメントは200文字以内で入力してください。
9. 指定された問い合わせは存在しません。
（N-02）他のユーザーが更新しました。画面を再読み込みしてください。

※ 原本PDF（p.9）で確認済み：R-02＝「完了済み…」、R-01＝「指定されたユーザー…」。「200文字」の間の空白はPDFの組版上の字間で、文字としての空白ではないと判断。

## F. 非機能（2.9）
- N-01：更新＋履歴登録を1トランザクション。履歴失敗で本体もロールバック
- N-02：画面に updated_at を hidden で保持し、更新時に一致確認
- N-03：権限チェックはすべてサーバー側（画面の非活性に依存しない）
